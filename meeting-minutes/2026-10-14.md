## Summary

### CIGAR Context Engine Demo Presentation

Ty presented a demo of CIGAR (Context Intelligence Graph Agentic Runtime), a context engine created with the open standards body HOL, designed for provable replay and authenticity verification of agent actions. The demo was built using draft 5 of AAC (or possibly AAIFs, which Ty clarified might be an IETF standard). Ty mentioned he would update the demo with the new draft 6 and host it in HOL, along with instructions for setting up a Hedera account for the full end-to-end SCIT part.

### Secure AI Payment System Demo

Ty demonstrated a secure AI agent payment system using Cigar and Hedera testnet, showing how the system restricts access to only approved information and enforces payment limits of £50,000. The demonstration included a complete transaction flow where the agent paid £48,200 to a supplier, with all actions recorded in an immutable and tamper-evident manner on the public ledger. The system provides cryptographic proof of what information was available to the agent, what actions were taken, and includes verification hashes in a Merkle tree structure to ensure auditability without trusting the AI system itself.

### CIGAR Security Protocol Discussion

The discussion focused on CIGAR, a security protocol for agent execution, with Manu explaining three key verticals: agent constraining, pro forma invoicing for tax compliance, and identity interoperability across enterprise and network boundaries. Ty clarified that CIGAR is not a blockchain solution but can work with blockchain and other systems, highlighting its successful 24-hour soak test with twelve agents that processed over a million events with zero errors. Ty also mentioned his work on open sourcing Humidor, which allows multiple CIGAR instances with graph-to-graph authentication, and noted that their communication protocols and identity standards are being used by companies like GoDaddy.

### SIGAR Authentication and Certification Systems

Ty explained that HCS 14 can be built for any authentication token and used as a unique identifier to get verification certification, allowing agents to be trusted based on user-defined certification systems rather than creating universal trust scores. Manu inquired about SIGAR identity interoperability across different agent registries, to which Ty responded that SIGAR can work with various authentication methods including DIDs and DNS. Marc suggested adding a KYC layer to establish liability for agents, which Ty noted could be implemented in practice rather than as a technical requirement within SIGAR. Ty mentioned he would update the demo and share it on GitHub and Discord.
